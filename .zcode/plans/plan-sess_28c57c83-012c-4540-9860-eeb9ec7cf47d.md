# Custom Fields + shadcn Select & Calendar

## Scope (per user choices)
- **Custom field types:** Text, Dropdown (single-select), Date — defined **per project**
- **Calendar:** shadcn Popover + Calendar replaces the native date input for the task due date
- **Dropdowns:** all native `<select>`s upgraded to shadcn Select (priority, assign-to, new field controls)

## 1. Database schema (`drizzle/schema.ts` + new migration)
Two new tables:

- **`project_fields`** — `id`, `projectId` (FK cascade), `name` varchar(60), `type` mysqlEnum `["text","select","date"]`, `options` json (string array, for select type), `sortOrder`, timestamps. Unique index on `(projectId, name)`.
- **`task_field_values`** — `id`, `taskId` (FK cascade), `fieldId` (FK cascade), `value` varchar(2000) nullable (dates stored as `YYYY-MM-DD` strings). Unique index on `(taskId, fieldId)`.

Generate `drizzle/0004_*.sql` with `drizzle-kit generate` (offline; apply via `db:push` if a local `DATABASE_URL` is available, otherwise the platform migration applies it on publish).

## 2. API — `server/routers/tasknest.ts`
New `field` sub-router (all `protectedProcedure`, guarded by `assertProjectMember`):
- `field.list` (projectId) → field definitions for the project
- `field.create` (projectId, name 1–60 chars, type, options ≤ 20 × 80 chars required for select) — rejects duplicate names per project
- `field.update` (fieldId, name?, options?) 
- `field.delete` (fieldId) — cascades to stored values

Extend task procedures:
- `task.create` / `task.update` accept optional `fieldValues: [{fieldId, value}]` (≤ 30 entries): validate each field belongs to the task's project, select values must match a defined option, date values must parse; write with replace-all semantics (like assignees). Empty string = clear.
- `task.detail` returns the task's `fieldValues` (field name/type/options joined) so the drawer and edit dialog can render them.
- Activity logging reuses the existing `task_updated` event type.

## 3. Client components (new files, keeping Home.tsx from growing)
- **`client/src/components/TaskCustomFields.tsx`** — renders controls for a project's fields with a `values` record + `onChange`: `Input` for text, shadcn `Select` for dropdown fields, shadcn `Popover`+`Calendar` (with a trigger button and clear option) for date fields. Used in both the create-task and edit-task dialogs.
- **`client/src/components/ProjectFieldsManager.tsx`** — "Custom fields" section inside the **project Edit dialog**: list existing fields (name, type badge), add a field (name + shadcn Select for type + options input for dropdowns), delete a field. Uses `field.create` / `field.update` / `field.delete` mutations with `toast` feedback and cache invalidation.

## 4. `client/src/pages/Home.tsx` integration
- Query project fields when a project is active (`trpc.tasknest.field.list`).
- Create-task dialog: include `TaskCustomFields` (empty values) and submit `fieldValues` through the existing `task.create` mutation.
- Edit-task dialog (in `TaskDrawer`): same component seeded from `task.detail`'s `fieldValues`; submit through `task.update`.
- Task drawer: read-only "Custom fields" section beside Due/Status showing stored values (dates formatted).
- **Select upgrades:** priority selector and assign-to selector become shadcn `Select` (same options/behavior, better styling and keyboard a11y).
- **Due-date upgrade:** native date input in the edit dialog becomes a shadcn `Popover` + `Calendar` picker (styled to match the Signal Desk palette) with a clear-date control.
